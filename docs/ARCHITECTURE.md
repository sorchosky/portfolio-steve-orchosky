# Architecture — steveorchosky.com

> One pass at project start, then edit only when a decision actually changes.
> If this drifts from what's actually in the repo, DECISIONS.md is where the
> drift gets recorded, not here.

## Stack

- **Framework:** None — static HTML/CSS/JS built by Gulp 5. Deviates from the
  React/Vite default. A migration to Astro is planned (see `docs/DECISIONS.md`)
  but hasn't landed yet.
- **Deploy:** Vercel, connected to `main` (production) / `dev` (staging).
  `vercel.json` sets `buildCommand: npm run build`, `outputDirectory: build`.
- **Styling:** Sass (`src/scss/`), compiled with `gulp-sass` (dart-sass) +
  `gulp-autoprefixer`. Bootstrap 4.5.3 imported a la carte via
  `src/scss/bootstrap.scss` (only the partials the site actually uses — see that
  file's comment list for what's included vs. commented out).
- **Templating:** `gulp-file-include` (`@@include`, `@@loop`, `@@if`) — HTML
  partial includes and simple loops, not a real templating language.
- **State management:** None. A handful of small vanilla-JS files
  (`src/js/*.js`), concatenated into one `scripts.js` at build time, run
  client-side for the nav toggle, project lists, prev/next navigation, and
  ScrollReveal / slick-carousel init.
- **External APIs:** None with a cost attached. CDN-loaded: Google Analytics
  (Universal Analytics tag `UA-60017587-1` — see watch-list below), Font Awesome
  5.15.1, ScrollReveal (unpinned, `unpkg.com/scrollreveal`), slick-carousel CSS/JS,
  jQuery slim + Popper + Bootstrap 4.0.0 JS (all via CDN in
  `src/html/components/source.html` / `head.html`).
- **Data/persistence:** None. Project and job-history data are plain JS array
  literals checked into source (see Data model below).

## Data model

No database — content lives in source files, duplicated across a few places
rather than centralized:

- **`src/js/projectArray.js`** — array of project objects
  (`projectId`, `title`, `mobileImg`, `desktopImg`, `projectCoverImg`,
  `processCoverImg`, `description`, `url`, `isPublic`, `featured`). Drives the
  featured-projects nav menu (`projectLoopMenu.js`) and the prev/next case-study
  navigation (`prevNextProjects.js`), both computed client-side at page load.
- **Inline `@@loop` JSON in `src/html/pages/index.html`** — a second, separately
  maintained list of the same projects, rendered into the homepage grid at
  build time by `gulp-file-include`. Not derived from `projectArray.js`.
- **`src/js/jobListArray.js`** — array of job/role objects, rendered into the
  About page's work-history list client-side (`jobLoop.js`).
- **Per-page hardcoded metadata** — each `src/html/pages/*.html` sets its own
  `<title>` and cover image inline via the `@@include('../components/head.html',
  {"title": ...})` parameter and its own markup. These have already drifted from
  the other two lists at least once (`store-mode.html`'s title reads "Smart Entry
  Mobile App | Steve Orchosky").

Net effect: adding or editing a case study currently means touching 3-4 files
by hand with no single source of truth. This is the main thing the planned
Astro migration collapses into one `src/data/projects.ts`.

## Key architectural decisions made up front

- Static Gulp build kept as-is for the initial Vercel hosting setup, rather than
  migrating the build tool first — smaller, reversible, ships hosting today — 2026-08-23
- `bootstrap` pinned to `4.5.3` to match `src/scss/bootstrap.scss`'s import list,
  rather than upgrading to the `^5.3.5` `package.json` had drifted to — 2026-08-23
- Three-tier branch model (`main` production / `dev` staging /
  `feature/*` work branches) adopted from vibe-scaffold — 2026-08-23

## Known constraints / things to watch

- **`build/` is committed and mixes generated output with source assets.**
  `build/*.html`, `build/style.css`, `build/bootstrap.css`, `build/scripts.js`
  are regenerated by `npm run build`; `build/img/` (473 files), `build/prototypes/`,
  `build/steve_orchosky_resume.pdf`, and `build/raynor.html` (no matching
  `src/html/pages/raynor.html` — orphaned) are not. Don't `rm -rf build/` or
  gitignore it wholesale; those files have no other home yet.
- **CDN dependencies are unpinned or stale.** `unpkg.com/scrollreveal` has no
  version pin at all. `source.html` loads Bootstrap **4.0.0** JS/Popper/jQuery
  from CDN against Bootstrap **4.5.3** compiled CSS — a version mismatch that
  happens to work today but is fragile. slick-carousel is loaded from CDN in
  `head.html` *and* vendored into the `scripts.js` bundle via `src/js/slick.js` —
  loaded twice.
- **Universal Analytics tag (`UA-60017587-1`) stopped processing data in July
  2023.** Site ships the script but nothing is being collected. Noted, not
  fixed as part of the hosting setup.
- **Sass `@import` is deprecated** in current dart-sass and will be removed in
  Dart Sass 3.0 — the build emits deprecation warnings (from Bootstrap's own
  source, not this project's), not errors. Harmless today, will need `@use`
  eventually.
- **`gulp-autoprefixer@9.0.0` is ESM-only.** `gulpfile.js` requires
  `.default` explicitly to work under Node's CJS interop — don't drop that if
  the import line is touched.

## Folder structure

```
src/
  html/
    pages/        one file per route, @@include-based templates
    components/    header, footer, head, and small repeated partials
  scss/
    helpers/       variables, fonts, mixins, utilities
    components/    per-component styles
    layouts/       per-page-type styles
    bootstrap.scss  Bootstrap 4.5.3, a la carte imports
    style.scss     everything else
  js/              one file per concern, concatenated into scripts.js
build/             gulp's output — see watch-list above
docs/              this file, PRD.md, DECISIONS.md
scripts/           new-feature.sh (worktree + branch creation)
```

Deviates from the Vite/React default entirely — see Stack above.
